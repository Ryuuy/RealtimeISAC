## 一句话结论

1. 实时链路（`rt_main.py`）真机能跑：20 s、1000 步、p99 4.4 ms（预算 20 ms）、overflow/late/timeout/丢步全 0；`--save-h` 与 `--debug` 同时开正常落盘。
2. 一开始看到的"正负多普勒对称"是**积分窗放错**：窗大半落在 ch0 的 OFF 段，积出来的是噪声。换成 ON 段内的窗后出现明显不对称的多普勒轨迹。
3. 把 NTG 的 Master/Slave 对调后（让参考通道稳定看到 Master 的突发），TDD 只剩一个稳定突发、占空 70.3–71.5%、对比度 0.92–1.00，窗不再跳。
4. 在 ON 段稳定的前提下，现有 live 切窗逻辑与"手工优化窗"几乎没有区别（见下表）；ON 段每秒漂 ~2.4 µs，`TddSync` 每 0.2 s 重估一次已经能跟上。
5. 实时链路与离线回放的频谱逐帧一致（见 §6）。
6. 方向指标：用 `D = P⁺ − P⁻`（线性）再转带符号 dB，比归一化比值 R 更"信能量"；穿越 LOS 前为正、穿越后为负，三次穿越都成立。**符号与"靠近/远离"的物理对应尚未标定。**

### 切窗策略回放（`scripts/window_strategy_replay.py`，`figs/winreplay_155600.png`）

用真实的 `TddSync` + `DopplerEngine` 逐步回放，动作段（5–12.5 s）高出静态底噪的 dB 数：

| 策略 | 高出底噪 | 与 live 谱相关 |
|---|---|---|
| live（现有，每 0.2 s 重估） | 36.3 dB | 1.000 |
| frozen（开头锁一次） | 36.3 dB | 0.998 |
| 固定在结尾的窗 | 36.1 dB | 0.995 |
| 不切窗（整周期） | 36.6 dB | 0.991 |
| narrow（只 300 µs） | 33.3 dB | 0.977 |

live 的 phase 20 s 内 1560→2030（47 µs），共移动 48 次。frozen 20 s 内没事只因为时间短；
按 2.4 µs/s，一小时漂约 8.5 ms（≈8–9 个周期），不更新会完全错开。**sync 的更新不能关。**
丢锁（对比度 <0.30）后先沿用旧窗 5 次（≈1 s），再退回整周期积分；回放里整周期积分几乎一样好，所以降级是平缓的。

## 7. TDD 锁的是谁

`rt_sync.py`：折叠 ch0 的 I 分量功率，阈值取 p10 与 p90 的几何中点，找最长连续超阈段。p90 是 Master 的突发，p10 是底噪，
阈值比 Master 低约 20–25 dB，所以弱的 Slave NLOS 突发不会被并进去。三份对调后的数据里 ON 段只有一个，宽度 70.3–71.5% = Master 突发长度。
ch0 的 OFF 段电平（−47 ~ −62 dBFS）里是否有可分辨的 Slave 突发，**我分不清**（164300 的 OFF 段 −52 ~ −56 比其它的 −62 高 6–10 dB，可能是 Slave 也可能是下降沿拖尾）。可看 ch1 的折叠包络确认，未做。

## 8. 方向指标（`figs/asym_160836.png`、`cand_160836.png`、`ddb_*.png`）

符号约定：S[f] = 对最近 200 个 `dec`（1 kHz）加 Blackman 窗做 256 点 FFT；P(f)=|S[f]|²。

- `R_abs = (A⁺−A⁻)/(A⁺+A⁻)`，A = Σ|S|（+20…+500 Hz / −500…−20 Hz）；`R_pow` 同式用 |S|²。归一化比值在纯噪声下也可能很大。
- **`D = P⁺ − P⁻`（线性）→ `D_dB = sign(D)·10·log10(|D|/(N·floor))`**，N·floor = 静止段平均 |S|² × 单侧 bin 数，0 dB = 与噪声同量级。
- 注意：|D| 小于噪声时 log 为负，乘 sign 后符号反转，静止段会显得在 ±15 dB 乱跳——这是公式产物，不是真有信号（静止段正负频带能量比 0.98–1.01）。需要时把低于噪声的值截成 0。

对 160836（gain 20，三次穿越 LOS）的候选对比（"穿越前为正 / 穿越后为负"是从图上总结的预期，不是外部真值，有一定循环论证）：

| 方法 | 前为正 | 后为负 | 静止 p95 | 动作中位 | 分离度 |
|---|---|---|---|---|---|
| R_abs | 96% | 90% | 0.08 | 0.25 | 3.0 |
| R_pow | 99% | 90% | 0.19 | 0.61 | 3.2 |
| R_shrunk（分母加噪声项） | 99% | 90% | 0.10 | 0.56 | 5.9 |
| D_dB | 99% | 89% | 1.4 | 13.0 | 9.2 |
| D_gate_dB（先门限 10×底噪） | 99% | 90% | 0.88 | 13.0 | 14.8 |

用户后来要求直接看 `D = P⁺−P⁻` 的 dB 图、不加 10 dB 门限（`ddb_*.png` 两层：多普勒谱 + D_dB，时间轴对齐）。
我试过 ±10 dB 门限：静止段 0% 误通过，但全程只有 48% 的步骤通过，"穿越后"一侧偏弱（−5 ~ −20 dB，对"穿越前"的 +15 ~ +35 dB）会被滤掉，门限不公平。

文献检索（WebSearch，结果零散）：
复数谱的符号保留方向，幅度谱对频率符号对称会丢方向（[Wi-Fi Radar via Over-the-Air Referencing](https://arxiv.org/pdf/2602.05344)）；
Widar 类数据约定正频 = 靠近（[Wi-CBR](https://arxiv.org/pdf/2506.11616)）；被动 Wi-Fi 雷达里前后走对应正负多普勒（[UCL](https://sine.ni.com/cs/app/doc/p/id/cs-16238)）。
**没有找到把正负频能量比 / 差当方向指标的现成方法**，上面这些是我自己在数据上试的。

穿越 LOS 数据（`los_160336`/`asym_160836`）：三次穿越（≈8.1、12.4、18 s，ch0 功率各凸起一次）前后 D 的符号稳定翻转。
**符号与靠近/远离的物理对应没有标定**（`conj(ch0)·ch1` 的约定没对过真实方向），需要一次"朝设备走/背离设备走"的实验。
